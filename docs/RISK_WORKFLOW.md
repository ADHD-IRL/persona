# Threats, chains, and actions

## Connected risk review

Open Threats or Chains and select a scenario. The selection carries into the other library and Session tracker in this browser and workspace. Search names, descriptions, categories; filter by domain; sort by severity, name or recent changes. Views include Needs review, High priority (threats), No mitigation, Overdue actions, Monitoring and Archived. The URL preserves filters and the selected finding for bookmarking and returning to your work. Lists show 40 records per page.

Select a row to review details without leaving the list. Existing records start as Needs review. Record your evidence confidence, rationale and review status. Confidence is distinct from severity and is not a measured probability. Marking Reviewed records the current scenario context and time. New evidence or edits require review again. Changed scenario context or actions implemented/verified after review raise a reassessment flag. Reviewed does not mean that a threat has been resolved.

Open source analysis or source debate links to inspect provenance. Evidence you add is labeled supplied_unverified; generated chain evidence is model output. Suggested duplicate names are only candidates. Compare records, choose the record to keep, then Merge and archive current. Evidence and relationships move transactionally; the archived original retains its content and points to the kept record. Merges stay within one scenario. Chains require identical steps to preserve action references; distinct paths should remain separate.

Select records individually or select the current page to set domains and review status in bulk. Archive via review status; records are retained. Partial failures keep failed records selected for retry.

From a threat, Build linked chain opens the builder with its scenario and threat relationship. Each step can record enabling conditions, sources, uncertainties and existing controls. From a chain, Find intervention points opens Chain Breaker with that chain and scenario selected. Create intervention links an action to a specific step; Create mitigation links an action to the whole finding. Enter an action and observable completion criteria, then set a due date and status. Repeated saves of the same action title on the same finding/step reuse the existing action; a distinct title creates another. Chain steps with linked actions cannot be deleted, reordered or rewritten; preserve the path or create a separate chain for a revised path.

Session tracker in the Work sidebar provides a session dashboard with a searchable Follow-up step, with Open, Overdue and All filters. Implemented actions remain open until verified or rejected. Due dates are informational; the app does not send notifications. An action's completion does not automatically reduce severity or prove control effectiveness. Reassess through Analyze with SMEs.

Start analysis offers Threats and chains to examine. Use relevant suggestions (scenario, domain and keyword matching), search, and check up to 30 of each type. Only checked findings enter the debate; selected chains are included in both rounds. Review the selection whenever the scenario changes. Archived or missing selected findings must be replaced. The snapshot includes selected records so changes to their content, evidence or review state invalidate reuse.

Completed guided analyses automatically save the brief's top findings and synthesis chains into Needs review. These are model proposals; severity remains unassessed for extracted brief findings until you assess it. Review threats and Review chains links lead from results to the library. Repeated worker resumes do not duplicate the same generated findings. Duplicate suggestions help reconcile findings from different analyses. The queue captures the brief's top findings, not every claim in the transcript; use the full debate for a comprehensive review. Existing completed analyses are not retrospectively imported.
